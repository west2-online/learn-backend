# learn-backend 电商第一轮：数据库、TodoList 与网页登录

> 先给每天的“待会儿再做”找个地方：记下来、勾掉它，下次打开还能接着用。

本轮通过一个支持网页登录的简单 TodoList，认识 HTTP 请求、后端服务和数据库如何配合。用户功能会继续用于后续电商项目，这一轮先把待办和登录做好；Docker 为选学内容。

## 学习总览与知识点

刚接触后端、还不知道它负责什么时，先使用[入门提示词](prompts/round2/prompt1.md)，结合一次“打开页面、发出请求、读取数据、显示结果”的过程建立初步认识。暂时看不懂的术语可以记下来，先跟着小练习学下去，再回到项目中理解；不要求开始前就掌握所有概念，但提交时要能解释自己的实现。

| 知识点 | 本轮学习范围 |
| --- | --- |
| 后端基本概念 | 浏览器、服务器、接口和数据库各自负责什么，一次请求如何得到响应 |
| HTTP、GET 与 POST | 请求方法、路径、参数、请求头、请求体、响应状态码和 JSON；理解 GET 与 POST 的语义，不能用 GET 执行修改操作 |
| Spring Boot（Java 路线） | 启动一个 Web 服务，接收请求、处理业务并返回响应；其他语言学习对应框架 |
| SQL 与 MySQL | 表、字段、主键、约束，以及增删改查；能写出并解释项目中的基本 SQL |
| ORM 与数据访问 | 理解对象和表之间的映射；Java 推荐 MyBatis-Plus，理解它与 MyBatis 的关系及实际执行的 SQL，不能用框架调用替代 SQL 学习 |
| Apifox | 编写接口文档，发送请求，设置参数和登录凭据，检查响应并保存调试用例 |
| Docker（选学） | 了解镜像、容器和 Compose；有余力时尝试容器化运行应用与数据库 |

## 考察目标

1. **后端基本理解：** 能结合自己的项目说明请求从哪里来、后端做了什么、数据保存在哪里，以及响应如何返回页面。
2. **MVC：** 理解 Model、View、Controller 的职责，能结合项目说明；区分 MVC 与 Controller、Service、Mapper 等代码分层，不把两者直接等同。返回 JSON 的接口也要能说明页面与后端的协作关系。
3. **Cookie、Session、Token：** 能说明它们各自的作用、如何参与登录和后续请求，以及自己的项目怎样处理过期、退出和用户数据隔离。

## 推荐技术与学习资料

- 数据库：MySQL；

语言和框架可以替换，实际组合必须完成本轮功能、测试和可复现的运行要求。版本原则及 Java 资料见[第 0 轮](0-开始之前.md)，Go 资料见[Go 推荐资料](0-开始之前.md#go-第一轮资料)。

## 项目要求

### 1. 数据库

学习 MySQL 的表、字段、数据类型、主键、约束和基本 SQL 操作，并在项目中完成用户与待办数据的增删改查。

- 自行设计数据表，用户和 Todo 数据保存在 MySQL 中；
- 提供建表或迁移脚本，使空数据库能够完成初始化；
- 应用重启后，已保存的用户和待办仍可正常使用。

### 2. TodoList

实现待办的 HTTP 接口，支持：

- 创建待办；
- 查询列表和单条详情；
- 修改内容、标记完成或未完成；
- 删除待办。

待办至少包含标题、内容、完成状态和必要的时间信息。接口路径和数据结构自行设计，记录在接口文档中。非法参数、待办不存在或操作失败时，应返回明确结果。

### 3. 网页登录与鉴权

提供一个可在浏览器中操作的简单页面，完成：

- 注册、登录和退出；
- 查看、修改自己的基本信息；
- 修改密码；
- 登录后使用 TodoList。

需要实现鉴权：未登录时不能访问受保护的数据或执行相关操作；用户只能查看、修改和删除自己的待办与个人信息。登录失效或退出后，应重新登录才能继续访问受保护资源。

页面需要完成操作并展示结果和错误提示；视觉设计不计入本轮考核，可以使用简单页面或现成 UI 模板。

### 4. Apifox 接口文档与调试

使用 Apifox 整理并调试账号与 TodoList 接口，记录请求方法、路径、参数、必要的请求头、请求体和响应示例。对登录后才能访问的接口，按自己的方案设置登录凭据，并验证正常操作、未登录访问和越权访问。

提交可导入的接口定义及必要的调试用例，README 写明导入和运行方式；使用示例账号和占位配置，不导出真实密码或有效登录凭据。Apifox 调试不能替代浏览器操作验证，也不能仅凭一次成功响应认定功能完成。

### 5. Docker（选学）

完成必做内容后，可以自行编写应用的 `Dockerfile` 和 `compose.yaml`，使用 Docker Compose 启动应用与 MySQL。启动后能够从浏览器完成上述操作。不选做 Docker 时，提供本机应用与 MySQL 的初始化、启动和停止步骤即可。

提交的配置应支持数据库初始化，并提供所需配置的示例值。在保留业务数据的正常停止、再次启动后，已有用户和待办仍可使用。README 写明构建、启动、访问、停止和测试方式。

## 测试与异常处理

延续起步任务的要求：实现功能时同步验证正常、边界和失败情况，修复问题后保留回归测试。

自动化测试至少覆盖：

- Todo 的增删改查，以及非法参数、目标不存在的情况；
- 注册、登录、退出、个人信息和修改密码；
- 重复注册、错误密码、未登录访问；
- 用户访问或修改其他用户的数据；
- 登录失效及退出后的受保护接口访问；
- 数据库操作失败时，接口返回失败，不能伪造成功或留下不符合业务规则的数据。

测试要断言预期结果，不只打印响应。另记录一次浏览器操作、Apifox 接口调试和应用重启验证，检查核心功能、错误提示及数据保留情况；选做 Docker 的同学再补充容器启停验证。

密码不得明文存储，接口和日志不应泄露密码、登录凭据或内部错误细节；配置示例不包含真实密钥。异常应有便于排查的记录，不能吞掉错误后继续返回成功。

## 提交内容

从本轮开始，自行创建一个**独立的个人公开项目仓库**，提交链接到负责人指定入口。第三、第四轮继续在该商城仓库迭代，分别保留 Git 标签或 Release，不把后续项目源码交到本指南仓库。本轮提交包含：

- 后端源码、简单网页和依赖配置；
- 数据库建表或迁移脚本；
- 本机运行的配置示例；选做 Docker 时附上 `Dockerfile` 与 `compose.yaml`；
- Apifox 接口定义与必要的调试用例、自动化测试和 README。

README 写清运行环境、初始化与启动步骤、访问地址、测试方式与实际结果，以及未完成内容和已知问题。别人按说明应能启动项目并完成注册、登录和待办操作。

本轮需要答辩，时间以当届通知为准。遇到问题时，带上代码、错误和排查过程及时沟通。

## Bonus

完成基础功能和测试后，可以选做：

- 待办筛选、排序或分页；
- 待办截止时间；
- 可交互的接口文档。

额外功能不抵消缺失的数据库、鉴权、接口文档与调试或测试要求。Docker 不作为本轮通过的必要条件。
