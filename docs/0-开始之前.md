# 第 0 轮：开始之前

这份说明用于统一学习方式、技术版本和提交位置。读完后，直接进入第一轮任务。

## 我们考察什么

我们不限定语言和框架，重点看两项能力：

1. **信息搜集：** 找到相关资料，判断来源是否可靠、版本是否适用，遇到冲突时继续查证。
2. **思考与设计：** 理解问题，提出方案，说明取舍，并用实现和测试验证判断。

接触一项新技术时，先回答三个问题：

- 它解决什么问题，这个问题是否存在于当前项目？
- 它采用什么方案，关键机制如何工作？
- 它带来哪些收益、成本和限制？

## AI 怎么用

AI 可以帮助检索资料、解释错误、比较方案和检查遗漏，但版本、API 和配置要回到官方文档或实际运行结果核验。提交的项目必须能够自己解释、修改、调试和验证。

第一轮用于熟悉语法、调试和测试，主要代码请先自己写，再用 AI 排查问题或评审实现。从第二轮开始可以更充分地使用 AI 辅助开发。

提问时带上环境版本、当前代码或操作、预期结果、实际结果和已经尝试过的方法。保留真正影响实现的资料、决定和验证结果，不用提交完整聊天记录。需要分析具体场景时，可参考[用 AI 探索一个具体场景](架构阅读.md#借助-ai-探索一个场景)。

## 技术版本

各轮给出的技术栈是推荐路线。默认选择当前最新正式版；如果关键依赖、工具或运行环境尚未适配，再选择兼容版本，并在 README 记录实际版本和调整原因。

- Java：2026-09-19 核验时，第一至第四轮统一使用 **JDK 17+**（上限 25）和 **Spring Boot 3.5.x**：Spring Boot 3.5 是 3.x 系列的最后一个版本，官方[要求 Java 17 至 25](https://docs.spring.io/spring-boot/system-requirements.html)，JDK 选 17、21 或 25 等 LTS 版本都可以，不要超过 25。3.5 的开源支持已于 2026-06-30 结束，商业支持到 2032-06-30；学习阶段固定 3.5.x 并留意安全更新即可。后续升级前重新核对 Spring Boot 的 Java 兼容范围。
- Go：Go 版本 1.20+ 即可，推荐 1.26；hertz 和 go-zero 框架保持最新即可。

## Git 与 GitHub

Git 是这个考核的交付方式：第一轮用它提交作业，第二至第四轮用它持续维护个人仓库、留标签和 Release。开工前先完整走一遍下面的练习，之后每轮都会用到。

必做练习：

- 注册 GitHub 账号，设置头像，并开启 2FA（多因素认证）；
- 写一个个人主页 README，可以自己查资料把它做得好看一点；
- 阅读下面的入门资料，在本地走完 clone → 修改 → commit → push；
- 在 [Github-Introduction](https://github.com/west2-online-reserve/Github-Introduction) 仓库用 Bug Report 模板提一个 issue，按模板要求填写（Bug 的复现步骤可以自己编，例如 click xxx）；
- fork 上面这个仓库，在**本地**新增 `README.md` 写入自己的 GitHub ID，commit 后 push 到自己的 fork，再向主仓库发起一个 Pull Request。

最后一步务必在本地完成再 push，不要直接在 GitHub 网页上编辑，两种做法是可以区分出来的。至少练习 `init`、`status`、`add`、`commit`、`log`、`diff` 和分支操作；commit message 建议遵循常见规范（如 Conventional Commits），并用 `.gitignore` 排除构建产物和本地配置。

- [Git 与 GitHub 的超容易入门](https://west2-online.feishu.cn/wiki/Lsz9w3CiGinXzgkevtmceHZknrf)：本地仓库、提交、远程仓库和 Pull Request 入门。
- [Pro Git 中文版](https://git-scm.com/book/zh/v2)：Git 官方书籍，适合查阅分支、远程、合并和回退。
- [GitHub Docs：开始使用 GitHub](https://docs.github.com/zh/get-started)：账号、仓库、Issue 和 Pull Request。
- [GitHub Docs：使用 Git](https://docs.github.com/zh/get-started/git-basics)：Git 与 GitHub 的关系及命令行操作。
