# learn-backend 第三轮考核：电商业务与下单闭环

## 项目描述

### 关于项目：给工作室开一家周边小店

工作室准备卖一点自己的周边：文化衫、帆布袋、徽章……商品和价格发在群里，下单靠接龙，颜色、尺码和收货地址散落在聊天记录中。每次统计订单，都像在聊天记录里考古。

这次，在上一轮项目上开发一个**工作室周边商城后端**：管理员管理商品，用户挑选商品、管理购物车并提交订单。本轮完成日常选购和下单；付款、库存、发货与专项优化留到下一轮。商城主题可以更换，功能范围保持一致。

本轮开发支撑商城操作的 HTTP 接口，沿用已有的账号、登录鉴权、数据库和 Docker 环境。演示使用上一轮页面或接口调试工具，完整商城前端不在考核范围内。测试和异常处理继续沿用前两轮要求。

商城中有两类使用者：

- **管理员**负责整理类目、维护商品和规格、调整价格以及上下架；
- **普通用户**负责挑选商品、管理自己的收货地址和购物车，以及查看、取消自己的订单。

本轮经营一家店，只处理商品、购物车和订单创建与取消，不包含支付、活动、库存、发货、多商家入驻和售后系统。

### 1. 收货地址：这单寄到哪里

沿用上一轮的注册、登录和个人信息功能，为用户增加收货地址管理：

- 新增地址，记录收货人、联系电话和详细收货地址；
- 查看地址列表，修改或删除已有地址；
- 设置默认收货地址；
- 下单时从已有地址中选择本次使用的地址。

一个用户可以保存多个地址，例如宿舍和家里。默认地址用于方便选择，用户仍可以在下单时改选其他地址。

### 2. 商品管理：先把货摆上货架

管理员需要能够维护商品类目、商品以及商品的具体规格。

**类目管理：** 支持新增、查看和修改类目，例如“服饰”“包袋”“小物”。商品需要归入对应类目，本轮使用简单的单级类目即可。

**商品管理：** 支持新增商品、查看商品列表和详情、修改商品信息以及上架和下架。商品信息至少包含名称、介绍和所属类目。

**SKU 管理：** 一个商品可以有多个可购买的规格组合，每个组合有自己的编号、规格信息、价格和上下架状态，管理员能够新增、查看和修改这些内容。

例如，“工作室文化衫”是一个商品，“黑色 / M 码”和“白色 / L 码”是两个不同的 SKU。用户最终买到的是选定颜色和尺码的文化衫。徽章这类没有多种规格的商品，也可以只有一个默认 SKU。

### 3. 商品浏览：让用户知道自己在买什么

用户可以分页浏览已上架的商品，查看商品详情及其可选 SKU。

- 商品列表展示商品名称、类目和价格信息，并提供详情入口；
- 商品详情展示介绍、可选规格以及各规格的价格；
- 用户选择具体规格和购买数量后，可以加入购物车。

例如，用户打开文化衫详情，选择“黑色 / M 码”、数量 2，再把这两件加入购物车。只有一种规格的商品也应能够完成同样的购买操作。

### 4. 购物车：先放着，等会儿一起买

购物车用来管理用户准备购买的商品，至少支持：

- 将选定的 SKU 和数量加入购物车；
- 查看购物车中的商品名称、规格、价格和数量；
- 修改某项商品的购买数量，或将其移出购物车；
- 选择部分或全部购物车商品提交订单。

加入购物车并不代表已经下单。例如，用户放入了两件文化衫和一个徽章，可以只选择文化衫下单，徽章仍留在购物车中。完成下单后，本次已购买的购物车项应从待购列表中移除。

### 5. 提交订单：把“想买”变成一笔订单

用户从购物车选择商品和收货地址，提交前查看商品、规格、数量、金额和收货信息，确认后创建订单。结算确认作为下单流程的一部分实现。

一张订单可以包含多个 SKU。提交成功后返回订单编号和下单结果，用户能够查看这笔订单的完整内容：

- 订单编号、下单时间和订单状态；
- 每项商品的名称、规格、购买数量、单价和小计；
- 整张订单的总金额；
- 本次使用的收货人、联系电话和详细地址。

例如，用户购买两件单价 39 元的文化衫和一个单价 12 元的徽章，这笔订单包含两项商品，总金额为 90 元。用户拿到订单编号后，可以再次打开订单详情查看这次购买记录。

本轮的“下单成功”表示商城已经接收了购买请求，不代表用户已经付款或商家已经发货。

### 6. 订单查询与取消：买了什么，还能在哪里找到

用户可以查看自己的订单列表，并通过订单编号进入详情。

列表中展示订单编号、下单时间、金额和状态等概要信息；详情展示完整的商品明细与收货信息。即使一次买了多种商品，也应能看清每项买了多少、价格是多少。

用户可以取消已创建的订单，取消后仍能在订单记录中查看它，并看到对应状态。本轮订单流程只涉及创建和取消，不需要提前加入待支付、待发货、退款等后续状态。

完成后，应能连贯地使用这家小店：管理员创建类目并上架带有不同规格的商品，用户登录、保存地址、选购商品、从购物车下单，最后查询或取消这笔订单。

管理端也能按订单编号或状态查找订单，查看商品明细、金额和收货信息。这样店主能回答“这位同学买了什么”，下一轮才能继续安排收款和发货。

## 推荐技术栈

在第二轮自行创建的个人项目仓库中继续开发，提交本轮 Git 标签或 Release。技术栈为推荐，优先使用当前最新正式版，按[第 0 轮](0-开始之前.md)核验适配与升级。

| 用途 | Java 路线 | Go 路线 |
| --- | --- | --- |
| Web 开发 | JDK 17+、Spring Boot 3.5.x、Spring MVC | Hertz 或 go-zero |
| 数据访问 | MyBatis/MyBatis-Plus 或 Spring Data JPA | GORM |
| 数据库 | MySQL | MySQL |
| 测试 | JUnit | Go 标准测试工具、GoConvey |
| 运行环境 | Docker、Docker Compose | Docker、Docker Compose |

架构文章和开源代码入口见[架构阅读](架构阅读.md)。先完成自己的实现，再针对实际问题对照阅读；分层和代码结构自行设计。
