## 四阶段递进关系

```text
语言基础、HTTP 抓取与 JSON、打包、测试与异常处理
    ↓
数据库、TodoList、网页登录鉴权、Docker
    ↓
商品与 SKU、购物车、地址、下单与取消
    ↓
六域基础链路、自选专项、异步与重试、并发与压测
```

第二轮的用户功能在后续商城中继续使用，TodoList 后续可以移除。第三轮完成小店的日常选购与下单；第四轮覆盖用户、商品、交易（含支付）、活动、仓储和履约六个域，先跑通基础链路，再自选一个场景深入。专项接入商城，但不要求重新改造全部六个域。后三个阶段在同一个电商项目中持续迭代。

## 通用规则

### 必做、Bonus 与非目标

- 各轮项目描述中的基本功能与明确要求是本轮必做；
- Bonus 只能在必做内容完成后选择，不用于抵消缺失的核心功能；
- 文档明确列出的非目标不需要提前实现；
- 如果确实无法完成某项要求，应在 README 中列出未完成内容、原因和当前结果，禁止伪造演示或测试记录。

### 技术选择

- 技术栈是推荐，不硬性限定语言和框架；优先选择当前最新正式版，只有关键适配明显不足时再调整版本，不以旧版“更稳”为默认理由；
- 第一至第四轮统一使用 JDK 17+（上限 25）和 Spring Boot 3.5.x。具体兼容范围按[第 0 轮](0-开始之前.md#技术版本)核验；
- 数据库、缓存、消息队列、搜索引擎或 Agent 必须对应明确问题，不按组件数量评分；
- 金额、库存、权限和状态流转等规则必须由确定性后端代码校验，不能交给客户端、提示词或人工约定。

### 代码与安全

- 禁止提交真实密钥、访问令牌、生产数据或无法公开的个人信息；
- 密钥和环境差异使用环境变量或配置示例管理；
- 密码不得明文存储，用户只能访问自己有权限的数据；
- 依赖和运行时版本应固定到可复现范围；
- 生成代码和 AI 辅助代码也必须能够独立解释、修改和调试。

## 提交通则

第一轮 Java 作业提交到 [west2-online-reserve/collection-java](https://github.com/west2-online-reserve/collection-java) 的 [`work2/`](https://github.com/west2-online-reserve/collection-java/tree/main/work2) 目录，具体方式按该仓库说明和当届通知执行。采用其他语言（如 Go）的同学，第一轮提交入口以当届通知为准。

第二轮起，学生须自行创建独立的个人公开项目仓库，将链接提交到负责人指定入口。第二至第四轮在这个电商仓库持续迭代，每轮创建可追溯的 Git 标签或 Release；后续新项目同样由学生创建对应的个人仓库。

```text
collection-java/work2/            # 第一轮 Java
个人账号下的商城项目仓库/           # 第二至第四轮
```

每轮至少提交：

- 源代码和依赖配置；
- README 与本轮完成情况；
- 可复制的启动、测试和停止步骤；
- 数据库迁移或初始化方案；
- 自动化测试及必要的测试数据；
- API 文档、设计图或测试报告等本轮要求的产物；
- `.gitignore` 和不含真实凭据的配置示例。

第一轮的个人作业目录必须包含完整源码、依赖配置、README 和测试；Java 赛事查询任务还需包含自己编写的抓取脚本和抓取得到的本地 JSON 数据快照，并说明数据来源与抓取时间。仅上传 jar、截图或运行结果不视为提交。数据由学习者自行抓取，题目不提供数据文件。

从空环境按 README 无法启动和验证的项目，不视为完整交付。

## 关于答辩

第二轮至第四轮原则上需要答辩，具体安排以当届通知为准。答辩时间与作品提交截止时间应至少错开一天，给考核人员预留检查时间。

如果遇到技术困难、设备限制或时间冲突，应尽早联系负责人，并提供当前代码、错误信息和已经尝试的方法。负责人可以调整时间或缩小 Bonus，但不应在不同成员之间改变核心验收标准。

## 评价原则

评价优先级依次为：

1. 正确性、权限与数据安全；
2. 可运行、可测试和可复现；
3. 业务建模与异常路径；
4. 模块边界、代码可维护性和协作说明；
5. 性能、可靠性与拓展深度。

框架更新、服务数量、代码行数和中间件数量都不是独立加分项。未经测量的“性能优化”、没有故障验证的“高可用”和无法说明数据来源的测试数字不作为有效证据。
